5. Honest provider seams: DWLR as a real adapter, end silent synthetic fallback

Worth exploring ports & adapters
src/ingestion/base_provider.py:6
src/ingestion/dwlr_provider.py:11 (does not subclass Base)
src/ingestion/realtime_provider.py:159-163 (delegates to synthetic)
src/api/app.py:145-159 (rejects dwlr)
src/ingestion/data_loader.py:81 (dwlr → "ganges" remap)

Problem: the seam's contract is an illusion — realtime silently serves synthetic piezometers/static, DWLR conforms to no base contract (different constructor, different signature), and pinning a coordinate on DWLR data can silently switch you onto synthetic ganges.

Solution: split the base seam so each adapter honestly declares what it serves; give DWLR the base contract; make any fallback explicit and surfaced.

  • leverage: one seam, three honest adapters
  • tests can assert on a real DWLR fixture
  • silent data swaps become loud

Problem: the report's quota curves are sine waves and its RMSE tables are canned arrays, so it can disagree with the live system it claims to report; meanwhile the MPC exposes an entire tunable surface no caller can set, and the frontend posts parameters the schema silently drops.

Solution: render every report section from the LP / MPC / evaluator outputs; wire the solver's tunables through the request schema or delete them.

  • dead tunables stop masquerading as options
